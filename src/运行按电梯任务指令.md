# Piper 电梯按钮任务操作指南

当前实际配置以第2节完整启动命令为准；第2.1节列出所有参数定义、默认值和单位。

本文档用于启动 Piper 机械臂电梯按钮任务，完成 CAN 通信初始化、整套节点启动、机械臂初始化、视觉检查、Action 任务下发以及安全失能。

> **安全提示**
>
> 下述启动参数包含 `auto_enable:=true` 和 `enable_motion:=true`，机械臂会被自动使能，并允许 MoveIt 向真机下发运动轨迹。启动前必须清空机械臂工作空间，确认急停按钮可用，并以低速进行首次测试。出现不可控运动、碰撞风险或硬件异常时，应立即按下物理急停。

## 1. 初始化 CAN 通信

打开第一个终端，进入工作区并激活 CAN 接口：

```bash
cd /home/xie/wzl/elevate_ws
bash can_activate.sh can0 1000000
```

这一步必须最先执行。它会将 `can0` 配置为 `1 Mbps`，供 Piper 底层驱动使用；CAN 未正确初始化时，后续机械臂节点无法正常通信。

可用以下命令检查接口状态：

```bash
ip -details link show can0
```

## 2. 启动完整系统

首次使用或修改 `src/` 后，在第二个终端构建本工作区：

```bash
cd /home/xie/wzl/elevate_ws
bash build_wzl.bash
```

启动请使用 `run_wzl.bash`，它会核对控制包来自本工作区。相机驱动目前仍由原工作区提供。

启动 Piper 底层驱动、MoveIt、相机、视觉识别和电梯任务 Action 服务：

```bash

    home_joint_tolerance:=0.012 \
    coarse_lateral_error_min:=0.021 \
    coarse_lateral_error_max:=0.032 \
    moveit_velocity_scaling_factor:=0.12 \
    moveit_acceleration_scaling_factor:=0.1 \
    transition_velocity_scaling_factor:=0.40 \
    transition_acceleration_scaling_factor:=0.40 \

    retract_acceleration_scaling_factor:=0.15 \

    preplan_retry_timeout_sec:=60.0 \
```

### 2.1 参数定义：当前值与默认值

“当前值”指上面的完整启动命令；“默认值”指 `all.launch.py` 未显式传参时的值。
命令行显式值优先。`run_wzl.bash` 默认关闭自动使能和真机运动，当前命令显式开启它们。
所有距离都要留意单位：补偿和 TCP 偏移是 **m**，推进和退回距离是 **mm**。
修改启动参数需要重启 launch；重启后重新调用 `/initialize_arm`。

#### YOLO计算设备

CUDA检测返回True后，可在完整启动命令中增加 `device:=0`，指定第0张GPU。
`device` 是字符串参数；空字符串自动选择设备，`cpu` 使用CPU，`0` 使用GPU。
启动文件已显式指定字符串类型，避免数字0被ROS解析成整数导致节点退出。
修改启动文件后须构建 `piper_vision` 并重启launch。

#### 连续模式、预规划与20mm退回

| 参数 | 当前值 | 默认值 | 单位／范围 | 定义及影响 |
| --- | --- | --- | --- | --- |
| `close_panel_sequence` | `true` | `false` | 布尔 | 数字键之间不回Ready，使用锁定按钮位置；完成最后确认键后回Ready。失败时停止，不自动恢复运动。单键 `/press_button` 默认不携带内部连续标志，仍走单键流程。 |
| `preplan_sequence` | `true` | `true` | 布尔；配合close模式 | 全部目标采样完成后，首键运动前规划本轮所有接近、按压和退回段；任意段规划失败均不开始运动。关闭它则仍锁定目标，但逐段临时规划。 |

| `preplan_retry_timeout_sec` | `60.0` | `60.0` | s，0～600 | 连续模式整轮提前规划时，每个规划段遇到MoveIt明确返回失败，可从同一起点持续重试，直到该段首次尝试起约60秒后仍未成功。正数时以时间为准，不受上述次数参数限制；0恢复次数限制。取消、单次Action超时、控制器拒绝、执行失败和实测验收失败均不重试。 |
| `sequence_snapshot_acquire_timeout` | `15.0` | `15.0` | s，正数 | 连续模式在Ready处为每个按钮等待稳定视觉位姿的最长时间；普通单键采集仍使用 `target_acquire_timeout=5.0s`。只延长等待，不放宽3帧、3mm和3°稳定性条件。超时会报告最近有效样本数及最新样本年龄，本轮不会开始运动。 |

按当前参数，首键TCP理论法向距离从80mm变为14mm，再退20mm到34mm。
后续键在约34mm的TCP法向间距处转移，再推进20mm到按压目标。
这些是规划几何量，不能直接认为接触点距面板还有14mm或34mm；实际夹持工具要现场确认。
所有预规划段会碰撞检查；按压与退回还限制在法向窄通道内。执行前检查真实关节与
预规划起点差异，每段结束检查TCP到位。面板和机器人底座在本轮执行期间不能移动。

### 2.2 速度、等待与3秒要求

- 当前整轮规划在首键前完成，之后无需等待下一键视觉识别和临时规划。
- 没有按压后的固定停留设置；分段轨迹端点减速、真实到位稳定检查、执行接口交接仍会产生间隔。
- “按键间隔监测”使用两次推进验收完成的单调时钟时间差，尚没有物理按钮触发反馈。
- 提高transition只加快转移，press只加快推进，retract只加快退回；驱动速度设置仍影响各段执行。
- 已实现提前规划，不等于已实现轨迹端点混合；当前不能保证完全不停顿或所有间隔≤3秒。

## 3. 初始化机械臂姿态

待第二个终端中的全部节点稳定启动后，打开第三个终端并加载环境：

```bash
cd /home/xie/wzl/elevate_ws
source /opt/ros/humble/setup.bash
# run_wzl.bash 会加载正确的工作区环境
```

调用机械臂初始化服务：

```bash
ros2 service call /initialize_arm std_srvs/srv/Trigger "{}"
```

该服务会以受限低速将真机移动到 Ready 姿态。每次 Piper 驱动进程重新启动后，都必须成功调用一次，后续真实 Action 轨迹才会被接受。

同一驱动进程内重复调用不会再次移动机械臂，而会返回机械臂已经初始化。确认响应中包含：

```text
success: true
```

### 3.1 修改 `/initialize_arm` 的速度

`Trigger` 服务请求只有 `{}`，不能在下面这条服务命令中携带速度：

```bash
ros2 service call /initialize_arm std_srvs/srv/Trigger "{}"
```

速度必须在启动 `all.launch.py` 时修改以下三项：

```text
initialization_speed_percent:=20
initialization_duration:=6.0
initialization_max_step:=0.006
```

三项参数的作用不同：

- `initialization_speed_percent` 是 Piper 驱动速度百分比，允许范围为 1～20；
- `initialization_duration` 是插值运动的最短持续时间，增大它会让目标变化更慢；
- `initialization_max_step` 限制 50 Hz 下相邻目标的最大名义步长，减小它会在
  起点距离 Ready 较远时自动延长运动时间。

例如需要恢复到较慢的 12% 初始化，可在主 launch 命令中改为：

```text
initialization_speed_percent:=12
initialization_duration:=12.0
initialization_max_step:=0.002
```

修改后必须重启 `all.launch.py`；对已经运行的节点再次调用服务不会重新读取 launch
参数。同一驱动进程已经初始化成功时，重复调用也不会再次运动。

如果只是修改启动命令中的 `:=` 参数值，不需要重新编译，停止并重新运行 launch
即可。如果修改的是 `src/` 目录中的 Python 代码、YAML 或 launch 默认值，则必须先
停止所有正在运行的 `all.launch.py`，再在 `elevate_ws` 工作区根目录重新编译：

```bash
cd /home/xie/wzl/elevate_ws
source /opt/ros/humble/setup.bash
colcon build --symlink-install
# run_wzl.bash 会加载正确的工作区环境
```

编译期间不要启动 ROS launch，也不要在另一个终端并行执行第二条 `colcon build`。
看到所有包均为 `Finished <<<` 且最终没有 `Failed <<<` 后，才能重新运行第 2 节的
`all.launch.py` 命令，再调用 `/initialize_arm`。

## 5. 下发 Action 任务

系统提供两个 Action 服务，消息类型均为 `piper_msgs/action/PressButton`。

### 5.1 单按钮任务：`/press_button`

该 Action 用于识别并对准一个指定按钮，目标名称必须使用 YOLO 的精确类别名：

```bash

  "{target_name: 'key_8'}" --feedback
```

### 5.2 完整电梯流程：`/run_elevator_sequence`

该 Action 执行完整流程：

```text
逐位数字按钮 → 每位后回到 home_joint_positions → key_ok → 再次回位
```

例如执行 8 楼任务：

```bash
ros2 action send_goal /run_elevator_sequence \
  piper_msgs/action/PressButton \
  "{target_name: '8'}" --feedback
```

两位楼层会逐位执行。例如 `10` 的严格顺序是：

```text
key_1 → 回位 → key_0 → 回位 → key_ok → 回位
```

调用命令：

```bash
ros2 action send_goal /run_elevator_sequence \
  piper_msgs/action/PressButton \
  "{target_name: '16'}" --feedback
```

若发送空目标，则使用启动参数 `floor_number`。当前配置下会执行 3 楼任务：

```bash
ros2 action send_goal /run_elevator_sequence \
  piper_msgs/action/PressButton \
  "{target_name: ''}" --feedback
```

下发任务后应持续观察终端反馈、机械臂运动状态和周围环境。在当前任务结束前，不要重复发送新的 Action Goal。

## 6. 七关节归零服务：`/return_all_joints_zero`

当前 `all.launch.py` 默认使用 `start_joint_zero_return:=true`，因此不需要额外启动
节点。先确认服务存在：

```bash
ros2 service list | grep return_all_joints_zero
```

正常情况下应看到：

```text
/return_all_joints_zero
```

服务调用命令：

```bash
ros2 service call /return_all_joints_zero \
  std_srvs/srv/Trigger "{}"
```

该服务不是“回到电梯任务初始位置”，而是从当前姿态开始执行真正的七关节零位：

```text
1. MoveIt 将 joint1～joint6 规划并执行到 0 rad
2. MoveIt 将夹爪 joint7 规划并执行到 0 m
3. 使用新鲜 /joint_states 验收六轴和夹爪是否进入允许误差
```

当前总启动命令使用 `enable_motion:=true`，该值会传给归零节点，因此调用服务会
控制真机运动。只有在以下条件全部满足时才能调用：

1. `/initialize_arm` 已返回 `success: true`；
2. `/move_group` 和 `/move_action` 正常；
3. 当前没有 `/press_button` 或 `/run_elevator_sequence` 任务；
4. 已确认七关节零位路径不会与面板、底座或周围物体碰撞；
5. 操作者能够随时按下物理急停。

归零节点默认使用：

```text
zero_velocity_scaling_factor=0.10
zero_acceleration_scaling_factor=0.10
arm_zero_tolerance=0.01 rad
gripper_zero_tolerance=0.003 m
```

### 6.1 修改 `/return_all_joints_zero` 的速度

和初始化服务一样，`std_srvs/srv/Trigger "{}"` 本身没有速度字段。归零速度必须在
启动 `all.launch.py` 时通过以下参数设置：

```text
zero_velocity_scaling_factor:=0.10
zero_acceleration_scaling_factor:=0.10
```

`0.10` 表示 MoveIt 速度和加速度缩放均为 10%。例如希望归零更慢，可将主 launch
命令中的两项改成 5%：

```text
zero_velocity_scaling_factor:=0.05
zero_acceleration_scaling_factor:=0.05
```

允许范围为大于 0 且不超过 1.0。归零轨迹还会受到
`trajectory_speed_percent:=20` 的 Piper 驱动侧全局上限约束；两个百分比不能相加。
修改后必须重启 `all.launch.py` 才会生效。

如果只是修改第 2 节启动命令中的
`zero_velocity_scaling_factor:=...` 和
`zero_acceleration_scaling_factor:=...`，不需要重新编译，重启 launch 即可。如果
修改的是 `src/` 目录里的归零代码、YAML 或 launch 默认值，则先停止所有
`all.launch.py`，再在 `elevate_ws` 工作区根目录执行：

```bash
cd /home/xie/wzl/elevate_ws
source /opt/ros/humble/setup.bash
colcon build --symlink-install
# run_wzl.bash 会加载正确的工作区环境
```

确认构建成功后重新运行第 2 节的主 launch，检查服务重新出现，再调用归零：

```bash
ros2 service list | grep return_all_joints_zero
ros2 service call /return_all_joints_zero \
  std_srvs/srv/Trigger "{}"
```

成功时返回类似：

```text
success: true
message: joint1-joint7 reached zero
```

失败时 `success` 为 `false`，`message` 会说明原因，例如 `/move_action` 不可用、
MoveIt 规划或执行失败、关节反馈过期，或者最终零位误差超差。可在另一个终端查看
归零状态：

```bash
ros2 topic echo /joint_zero_return/state
```

如不需要该高风险服务，可在总启动命令中添加：

```text
start_joint_zero_return:=false
```

此时 `/return_all_joints_zero` 不会出现。

## 7. 停止系统与机械臂失能

正常停止时，应先等待当前 Action 完成，然后调用失能服务：

```bash
ros2 service call /enable_srv piper_msgs/srv/Enable \
  "{enable_request: false}"
```

确认机械臂已经失能后：

1. 在运行 `all.launch.py` 的终端按 `Ctrl+C` 停止 ROS 2 节点。
2. 等待节点完全退出。
3. 再关闭机械臂和相关设备电源。

不要通过直接切断电源代替正常失能。发生紧急情况时，不必等待软件服务响应，应直接使用物理急停。

## 8. 推荐操作顺序

```text
1. 清空工作空间并确认急停可用
2. 激活 can0
3. 启动 all.launch.py
4. 等待相机、驱动、MoveIt 和视觉节点稳定
5. 调用 /initialize_arm
6. 使用 rqt_image_view 检查按钮识别结果
7. 下发单按钮或完整流程 Action
8. 等待 Action 完成
9. 如确有需要且路径安全，单独调用 /return_all_joints_zero
10. 调用 /enable_srv 失能机械臂
11. 停止 launch，最后关闭设备电源
```
