# Piper 电梯按钮定位调试指南

## 单键点击测试参数（65毫米）

以下配置对应逐键点击测试脚本；粗定位采样时显式覆盖 `distance_mm:=0.0`。
连续任务当前使用67毫米行程及20毫米退回，以运行手册第2节的完整命令为准。
数值采样记录和计算示例中的历史数据仅供追溯。

```bash
cd /home/xie/wzl/elevate_ws
bash run_wzl.bash \
  auto_enable:=true enable_motion:=true \
  tcp_offset_z:=0.1358 distance_mm:=65.0 \
  coarse_horizontal_offset:=0.026 coarse_vertical_offset:=0.007 \
  coarse_lateral_error_min:=0.021 coarse_lateral_error_max:=0.032 \
  coarse_correction_attempts:=0 home_joint_tolerance:=0.012
```


本文档用于标定 Piper 机械臂的 Ready 初始位、按键后回位姿态、按钮水平及竖直补偿和粗定位
横向验收范围。内容以当前 `src/` 源码为准。

当前启动参数的完整定义、默认值和分阶段速度见 [运行手册第2.1节](./运行按电梯任务指令.md#21-参数定义当前值与默认值)。本文后面的历史采样数值不覆盖主手册当前配置。

相关文档：

- [运行按电梯任务指令.md](./运行按电梯任务指令.md)：完整系统启动和任务指令；
- [ROS功能包源码说明.md](./ROS功能包源码说明.md)：各功能包、节点和接口说明。

> **安全要求**
>
> 调试水平补偿和误差范围时，必须先设置 `distance_mm:=0.0`，只运行按钮前粗定位，
> 禁止向面板推进。确认所有按钮的粗定位均安全后，再单独调试按压距离。启动真机运动前
> 清空工作空间、确认物理急停可用，并安排人员随时观察末端与相机的碰撞风险。

## 1. 先分清四类参数

| 参数或服务 | 当前值 | 实际作用 |
|---|---:|---|
| `/initialize_arm` | 固定 Ready 姿态 | 把 joint1～joint7 从当前真实位置移动到代码中的 Ready 姿态 |
| `home_joint_positions` | 六个关节角 | 每按完一位楼层数字，以及按完 `key_ok` 后返回的六轴观察姿态 |
| `coarse_horizontal_offset` | `0.026` m | 沿按钮坐标系水平轴移动粗定位目标；正值向左，负值向右 |
| `coarse_vertical_offset` | `0.007` m | 沿按钮坐标系竖直轴移动粗定位目标；正值向上，负值向下 |
| `coarse_lateral_error_min/max` | `0.009/0.019 m` | 判断实测 TCP 横向距离是否合格；只负责验收，不会移动目标 |

这四项不能互相替代：

- `/initialize_arm` 决定启动后的 Ready 姿态；
- `home_joint_positions` 决定任务中每次按键后的回位姿态；
- `coarse_horizontal_offset` 用来实际修正左右对准位置；
- `coarse_vertical_offset` 用来实际修正上下对准位置；
- `coarse_lateral_error_min/max` 只决定粗定位成功还是失败。

## 2. 调试阶段推荐启动参数

调试定位时使用 `distance_mm:=0.0`，避免粗定位成功后继续按压。以下参数保留当前工程的
速度、home 和验收配置：

```bash
cd /home/xie/wzl/elevate_ws
source /opt/ros/humble/setup.bash
# run_wzl.bash 会加载正确的工作区环境

bash run_wzl.bash \

  auto_enable:=true \
  enable_motion:=true \
  initialization_speed_percent:=20 \
  initialization_duration:=6.0 \
  initialization_max_step:=0.006 \
  trajectory_speed_percent:=20 \
  coarse_standoff:=0.08 \
  x_advance_axis_mode:=panel_normal \
  coarse_correction_attempts:=0 \
  coarse_horizontal_offset:=0.026 \
  coarse_vertical_offset:=0.007 \
  tcp_offset_z:=0.1358 \
  distance_mm:=0.0 \
  floor_number:=3 \
  home_joint_positions:="[-1.557051440, 0.234953236, -0.324353736, 0.013745872, 0.203885472, -0.018106872]" \
  home_joint_tolerance:=0.012 \
  home_velocity_scaling_factor:=0.07 \

```

这里只修改 `ros2 launch` 参数值时，不需要重新 `colcon build`，但必须停止旧 launch 后
重新启动。修改 `src/` 中的源码、YAML 或 launch 默认值后，才需要在 `/home/xie/wzl/elevate_ws` 下
重新构建。

## 3. 第一步：确定 Ready 初始位置

完整系统启动、机械臂使能且反馈正常后，执行：

```bash
ros2 service call /initialize_arm std_srvs/srv/Trigger "{}"
```

当前代码中的完整 Ready 目标为：

```text
joint1 =  -1.557051440 rad
joint2 =  0.2349532360 rad
joint3 = -0.324353736 rad
joint4 =  0.0137458720 rad
joint5 =  0.203885472 rad
joint6 = -0.018106872 rad
joint7 =  0.002000000 m
```

该位置定义在 `src/piper/piper/trajectory_execution.py` 的 `READY_POSITIONS` 中。
`/initialize_arm` 是无参数 `Trigger` 服务，不能在服务命令里临时修改目标或速度。
初始化速度由启动参数 `initialization_speed_percent`、`initialization_duration` 和
`initialization_max_step` 控制。

确认服务返回：

```text
success: true
```

再观察机械臂是否具备以下条件：

1. 相机能完整看到电梯按钮面板；
2. 机械臂后续前往上、下、左、右边缘按钮均有足够关节余量；
3. 相机、末端和机械臂连杆没有贴近面板或其他障碍物；
4. `/joint_states` 的 joint1～joint6 与上述 Ready 值接近。

可读取一次真实关节反馈：

```bash
ros2 topic echo --once /joint_states
```

## 4. 第二步：设置按键后的 home 回位姿态

若要求“每次按完按钮都回到 `/initialize_arm` 的初始位置”，应把
`home_joint_positions` 设置成 Ready 的前六个关节值：

```bash
home_joint_positions:="[-1.557051440, 0.234953236, -0.324353736, 0.013745872, 0.203885472, -0.018106872]" \
home_joint_tolerance:=0.012 \
home_velocity_scaling_factor:=0.07 \
home_acceleration_scaling_factor:=0.07
```

注意：

- `home_joint_positions` 只接收 joint1～joint6，单位是 rad，不要添加 joint7；
- `[-1.557, 0.235, -0.324, 0.014, 0.204, -0.018]` 是近似值；若要与
  `/initialize_arm` 尽量一致，推荐使用上面的完整精度值；
- `home_joint_tolerance:=0.012` 表示配置容差为 0.015 rad；当前代码验收条件是
  `最大关节误差 < home_joint_tolerance + 0.001 rad`，即本配置实际要求严格小于
  0.016 rad；
- home 速度由 `home_velocity_scaling_factor` 和
  `home_acceleration_scaling_factor` 控制，与粗定位速度参数分开。

使用完整序列测试回位：

```bash
ros2 action send_goal /run_elevator_sequence \
  piper_msgs/action/PressButton \
  "{target_name: '3'}" --feedback
```

由于调试启动使用 `distance_mm:=0.0`，该任务只到达按钮前粗定位，不会继续向按钮推进。
一位楼层的状态顺序应为：

```text
key_3 粗定位 → RETURN_AFTER_NUMBER → key_ok 粗定位 → RETURN_AFTER_OK
```

终端出现下面的日志表示回位验收通过：

```text
【回位验收成功】最大关节误差=... rad，配置容差=... rad
```

## 5. 第三步：调 `coarse_horizontal_offset`

### 5.1 参数含义

代码先根据按钮中心 B0 和 `coarse_standoff` 计算未补偿目标 `C0_raw`，再沿按钮坐标系
局部 `+X` 加上 `coarse_horizontal_offset`，得到 MoveIt 目标 C0：

```text
C0 = C0_raw + coarse_horizontal_offset × 按钮局部水平轴
```

方向以人正对电梯面板为准：

| 观察到的末端位置 | 调整方式 |
|---|---|
| 末端在按钮右侧，需要向左 | 增大参数，例如 `0.014 → 0.016` |
| 末端在按钮左侧，需要向右 | 减小参数，例如 `0.014 → 0.012` |
| 仍需继续向右 | 参数继续减小，必要时变成负值 |

参数单位是 m，代码允许范围为 `-0.05～+0.05 m`。建议每次只调整 1～2 mm：

```text
0.001 m = 1 mm
0.002 m = 2 mm
```

修改启动参数后必须重启 launch。例如改为向左 16 mm：

```bash
coarse_horizontal_offset:=0.026 \
```

### 5.1.1 竖直补偿和本次观测

`coarse_vertical_offset` 沿按钮局部 `+Y` 调整目标，正值向上。2026-09-29 在
`key_8`、水平和竖直补偿均为 `0`、`distance_mm:=0.0` 时，粗定位 Action 成功；
实物观察为按压头向右约 25 mm、向下约 7.5 mm。这是单点测量，先以小步长复测：
水平 `+0.005 m`、竖直 `+0.002 m`；观察实际移动方向后再逐步逼近估计的
水平 `+0.025 m`、竖直 `+0.0075 m`。每次修改启动参数后都需要重启 launch，
并保持 `distance_mm:=0.0`。Action 的成功状态只说明软件验收通过，仍需核对
按压头与按钮的实际中心。

### 5.2 终端中应该看哪一行

粗定位成功时，控制器打印：

```text
【定位诊断】实测相对未补偿目标水平位移=+14.00 mm（正值向左，负值向右）
```

该值有正负方向，主要用于检查水平补偿是否真正执行到位。它通常应接近配置的
`coarse_horizontal_offset`，但会包含 MoveIt 实际执行误差。

粗定位失败时会打印：

```text
【粗定位验收超差诊断 4/4】C0目标TCP position=...
【粗定位验收超差诊断 4/4】T0实测TCP position=...
【粗定位验收超差诊断 4/4】T0-C0=...
【粗定位验收超差诊断 4/4】位置误差=...
【粗定位验收超差诊断 4/4】姿态误差=...
【粗定位验收超差诊断 4/4】法向距离=..., 法向距离误差=...
【粗定位验收超差诊断 4/4】横向误差向量=..., 模长=..., 允许范围=[..., ...] m
```

`T0-C0` 是 MoveIt 目标与实测 TCP 的执行误差；它不等于下面用于验收的“横向误差
模长”。

### 5.3 如何让多个按钮都对准

`coarse_horizontal_offset` 是所有按钮共用的一个全局水平补偿，不能给每个按钮设置
不同数值。因此应按下面顺序采样：

1. 先选择面板中间位置的按钮，调到末端物理中心对准按钮；
2. 再依次测试左上、右上、左下、右下和 `key_ok`；
3. 每次记录按钮名称、物理左右偏差、水平有符号位移、横向模长、法向误差和姿态误差；
4. 选择能让大多数按钮都对准的统一补偿值；
5. 再用全部按钮复测，而不是只看一个按钮成功。

建议使用下表记录：

| 按钮 | 物理观察 | 水平位移（有符号） | 横向模长 | 法向误差 | 姿态误差 | 是否对准 |
|---|---|---:|---:|---:|---:|---|
| `key_1` | 左/中/右 |  mm |  mm |  mm |  deg | 是/否 |
| `key_5` | 左/中/右 |  mm |  mm |  mm |  deg | 是/否 |
| `key_9` | 左/中/右 |  mm |  mm |  mm |  deg | 是/否 |
| `key_ok` | 左/中/右 |  mm |  mm |  mm |  deg | 是/否 |

如果一个补偿值只能对准部分按钮，而其他按钮的偏差随面板行列明显变化，不要继续单纯
放宽误差范围。此时更可能需要检查：

- YOLO 各按钮检测框中心是否准确；
- 深度和锁定面板平面是否稳定；
- 手眼标定 TF 是否准确；
- `tcp_offset_z` 和真实工具中心是否一致；
- 面板姿态、按钮局部坐标轴和相机安装是否存在系统偏差。

## 6. 第四步：根据正确对准样本设置横向验收范围

### 6.1 这两个参数不会修正位置

```bash
coarse_lateral_error_min:=0.021 \
coarse_lateral_error_max:=0.032 \
```

控制器计算按钮中心 B0 到实测 TCP T0 的向量，去掉面板法向分量后，得到面板切平面内
的横向误差向量，再取模长：

```text
lateral_error = |B0-T0 在面板切平面内的分量|
```

因此“横向误差模长”有以下特点：

- 单位是 m；
- 永远是非负数，没有左右方向；
- 同时包含面板平面内的水平和竖直分量；
- 只有落在闭区间 `[min, max]` 内才通过验收；
- 修改该范围不会让机械臂向左或向右移动。

当前 `coarse_horizontal_offset:=0.026` 会故意引入约 14 mm 的水平偏置，所以代码使用
9～19 mm 的横向模长闭区间来包围预期补偿。这里的“横向误差”是几何验收量，不应简单
理解为越接近 0 越好。若实际工具不需要这种偏置，应重新设计补偿和下限，不能只保留
9 mm 下限。

### 6.2 从终端日志取值

成功或失败诊断中都要关注：

```text
横向误差向量=(...), 模长=0.019254 m, 允许范围=[0.0090, 0.0190] m
```

这个例子中的 `0.019254 m = 19.254 mm`，大于上限 19 mm，所以横向验收失败，即使只
超出 0.254 mm 也不会通过。

但粗定位最终通过还必须同时满足：

| 验收项 | 当前条件 |
|---|---|
| 法向距离误差 | `abs(法向误差) <= 0.010 m` |
| 横向误差模长 | `0.009 m <= 模长 <= 0.019 m` |
| 姿态误差 | `<= 1.5 × 0.05 rad = 0.075 rad`，约 4.30° |

所以横向模长进入范围后仍失败时，还要检查法向误差和姿态误差，不能只继续放宽横向
范围。

### 6.3 推荐的取值方法

只使用“末端物理上确实对准按钮”的样本计算范围：

1. 每个按钮至少重复 3 次，记录终端打印的横向模长；
2. 删除视觉跳变、深度异常和明显未对准的样本；
3. 记正确样本的最小值为 `L_min`，最大值为 `L_max`；
4. 根据重复误差在两端增加 1～2 mm 余量；
5. 设置：

```text
coarse_lateral_error_min = max(0.0001, L_min - margin)
coarse_lateral_error_max = L_max + margin
```

例如所有正确对准样本落在 11～17 mm，使用 2 mm 余量，可先设置为：

```bash
coarse_lateral_error_min:=0.021 \
coarse_lateral_error_max:=0.032 \
```

这只是计算示例，不代表所有机械臂都应固定使用该范围。代码要求两个值都大于 0，并且
`coarse_lateral_error_min < coarse_lateral_error_max`。

不要把未对准按钮产生的大误差也纳入范围。否则程序会把错误位置判定为成功，并在恢复
`distance_mm` 后继续向面板推进。

## 7. 逐个按钮复测

保持 `distance_mm:=0.0`，使用完整序列测试每个数字。这样每个数字粗定位完成后都会回
home，随后测试 `key_ok` 并再次回 home：

```bash
ros2 action send_goal /run_elevator_sequence \
  piper_msgs/action/PressButton \
  "{target_name: '1'}" --feedback
```

依次把目标改为 `2`、`3`……`9`、`0`。两位楼层也按每一位分别定位和回位，例如：

```bash
ros2 action send_goal /run_elevator_sequence \
  piper_msgs/action/PressButton \
  "{target_name: '10'}" --feedback
```

执行顺序为：

```text
key_1 → home → key_0 → home → key_ok → home
```

也可直接测试单个按钮：

```bash
ros2 action send_goal /press_button \
  piper_msgs/action/PressButton \
  "{target_name: 'key_5'}" --feedback
```

但 `/press_button` 成功后会保持在粗定位末端位置，不会自动返回 home；需要自动回位时
优先使用 `/run_elevator_sequence`。

## 8. 确认参数已生效

每次重启 launch 后，可查询运行时参数：

```bash
ros2 param get /piper_pbvs_controller coarse_horizontal_offset
ros2 param get /piper_pbvs_controller coarse_lateral_error_min
ros2 param get /piper_pbvs_controller coarse_lateral_error_max
ros2 param get /elevator_sequence home_joint_positions
ros2 param get /elevator_sequence home_joint_tolerance
```

预期终端还会打印：

```text
【粗定位水平补偿】+14.0 mm（正值向左，负值向右）
```

如果查询值仍是旧值，通常表示旧 launch 没有完全退出、当前终端没有加载最新
`install/setup.bash`，或者修改了 `src/` 默认值但尚未重新构建。

## 9. 最终按压前检查

只有下面项目全部通过后，才恢复非零 `distance_mm`：

- Ready 初始位安全且视觉完整；
- 每次按键后都能稳定返回 home；
- 所有按钮的末端物理中心都已对准；
- 正确样本的横向模长全部落在验收区间；
- 法向误差和姿态误差也通过；
- 没有通过放宽范围接纳错误位置；
- 已确认 `x_advance_axis_mode:=panel_normal` 的方向正确；
- 急停和面板前工作空间已再次确认。

恢复 `distance_mm` 后应从经过验证的安全小位移开始逐步增加。当前系统没有力/触觉、
按钮行程或按钮灯闭环，MoveIt 到达设定位姿不等于按钮一定已经触发。


## 自动逐键粗定位监测

先启动 `run_wzl.bash`，保持 `distance_mm:=0.0`、
`coarse_correction_attempts:=0`，完成初始化并确认机械臂位于 Ready。
测试期间不要从其他终端或 RViz 下发运动任务。脚本不修改补偿或验收阈值，
不调用七关节归零服务。

```bash
cd /home/xie/wzl/elevate_ws
bash test_buttons_wzl.bash
```

顺序：`key_5 → key_1 → key_3 → key_7 → key_9 → key_0 → key_2 →
key_4 → key_6 → key_8 → key_ok`。每键粗定位后停留 5 秒，再由 MoveIt
回到配置的 Ready，并验证真实关节反馈。可指定面板实际存在的按钮：

```bash
bash test_buttons_wzl.bash key_8 key_5 key_1 key_ok --pause 10
```
